# 20260706231710. Spec과 ADR 중심 문서 모델 채택

Status: Accepted

## Context

StateTrail은 제품과 아키텍처가 바뀌어도 계속 유용한 문서 모델이 필요합니다.
임시 구현 메모, 제안 초안, 리서치 노트는 변경을 진행하는 동안 도움이 되지만,
나중에 저장소를 읽는 사람과 에이전트의 기본 판단 근거가 되어서는 안 됩니다.

오래 남기는 문서 모델은 다음을 구분해야 합니다.

- 사용자와 유지보수자가 의존할 수 있는 관찰 가능한 제품 동작
- 시스템이 특정 형태를 갖게 된 이유를 설명하는 아키텍처와 프로세스 결정
- 진행 중인 Spec 변경을 리뷰하고 구현하기 위한 임시 패키지
- 활성 프로젝트 지침으로 취급하지 않아야 하는 로컬 리서치와 초안

## Decision

StateTrail은 오래 남기는 문서를 Spec과 ADR 중심으로 유지합니다.

Spec은 `openspec/specs/` 아래에 두며, 제품이 무엇을 하는지, 어떤 보장을
노출하는지, 어떤 시나리오가 계속 동작해야 하는지를 설명하는 관찰 가능한
동작 계약입니다. Spec은 제품 동작에 대한 기본 장기 참조입니다.

ADR은 `docs/adr/` 아래에 두며, 이후 변경을 제약하거나 안내해야 하는
아키텍처 또는 프로세스 결정의 맥락, 결정, 결과, 트레이드오프를 설명합니다.

`openspec/changes/<change>/`는 Spec Change 리뷰 패키지입니다. 그 안의
`proposal.md`, `design.md`, `tasks.md`, spec delta는 해당 변경을 리뷰하고
구현하기 위한 자료이며, 독립적인 장기 문서 종류가 아닙니다. 사람과
에이전트는 그 변경을 작업하거나 변경 이력을 확인할 때만 해당 패키지를
읽습니다.

`openspec/changes/archive/`는 이력 기록입니다. 이전 변경이 어떻게 반영됐는지
설명할 수 있지만, 일반 구현 작업의 활성 지침은 아닙니다. 활성 동작 지침은
`openspec/specs/`에서 읽고, 장기 결정 근거는 `docs/adr/`에서 읽습니다.

`docs/research/`는 ignored 로컬 리서치와 초안 공간으로 유지합니다. 리서치
노트는 이후 Spec이나 ADR의 재료가 될 수 있지만, 관련 결론이 tracked Spec
또는 ADR로 승격되기 전까지는 저장소 지침이 아닙니다.

## Consequences

사람과 에이전트가 기본으로 읽는 오래 남는 위치는 두 곳입니다.

- 제품 동작 계약은 `openspec/specs/`
- 아키텍처와 프로세스 결정 근거는 `docs/adr/`

Spec Change 패키지 파일은 리뷰와 구현 중에는 유용하지만, 변경이 완료된 뒤
현재 계약으로 인용하지 않습니다. Spec은 현재 시점의 리뷰 가능한 동작
계약이며, 오래 남는 지침일 뿐 불변의 최종 결정이 아닙니다. 변경이 오래
남는 동작을 바꾸면 Spec을 추가하거나 수정합니다. 변경이 오래 남는
아키텍처 또는 프로세스 결정을 만들면 ADR을 추가합니다.

리서치와 초안은 가볍고 로컬인 상태로 둘 수 있으며, 저장소의 판단 근거를
오염시키지 않습니다.
